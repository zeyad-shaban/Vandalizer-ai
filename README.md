# Vandalizer AI Workspace

Research and prototyping workspace for Vandalizer, an AI image editing app for detecting, masking, and removing or replacing objects in images.

[Live app](https://vandalizer-frontend.vercel.app/) | [Backend Space](https://huggingface.co/spaces/zeyadcode/vandalizer-backend) | [Demo video](https://youtu.be/dkpUaaLSOQU)

## Related Repositories

- [vandalizer-frontend](https://github.com/zeyad-shaban/vandalizer-frontend) - React/Vite UI for upload, mask editing, and result generation.
- [vandalizer-backend](https://github.com/zeyad-shaban/vandalizer-backend) - FastAPI, Celery, Redis, and model inference service.
- [vandalizer-ai-workspace](https://github.com/zeyad-shaban/vandalizer-ai-workspace) - this notebook workspace for experiments and model choices.

## What This Repo Is

This is the experimental side of Vandalizer. It is not meant to read like a polished academic benchmark. It is a personal learning and prototyping space used to compare model options, test inpainting behavior, export faster inference formats, and turn promising experiments into backend code.

The production app is split across the frontend and backend repos. This workspace explains how the AI parts were explored before being wired into the backend.

## Experiment Areas

| Area | Files | Purpose |
| --- | --- | --- |

## Models and Tools Explored

- GroundingDINO for early zero-shot detection experiments.
- OWLv2 for prompt-based object detection.
- OpenVINO for CPU-friendly optimized inference.
- SAM, FastSAM, and MobileSAM for mask generation.
- SimpleLama for object removal.
- Stable Diffusion inpainting pipelines for prompt-guided replacement.
- Optimum Intel for OpenVINO diffusion pipelines.
- Pillow, OpenCV, NumPy, Matplotlib, and PyTorch for image processing and visualization.

## How It Connects to the Backend

The backend uses the lessons from this workspace in a production-style API:

- OWLv2 became the text-prompted detector.
- MobileSAM became the segmentation model for turning boxes into masks.
- SimpleLama powers the `remove` mode.
- OpenVINO diffusion pipelines were tested for prompt-guided replacement.
- Mask conversion, binary mask generation, visual overlays, and blur behavior were moved into backend utilities.

## Running Notebooks

This repo does not currently pin a dedicated notebook requirements file. The backend requirements cover most runtime libraries, and the notebooks also use common research tools such as Jupyter, Matplotlib, Supervision, Requests, and ONNX Runtime.

Example setup:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r ../vandalizer-backend/requirements.txt
pip install jupyterlab matplotlib supervision requests onnxruntime
jupyter lab
```

If you clone this repo by itself, install the backend dependencies manually or copy the backend `requirements.txt` into the workspace before running the notebooks.

## Notes for Reviewers

This repo is useful if you want to understand how the model stack evolved. The notebooks show practical exploration: trying detectors, testing segmentation quality, checking inpainting approaches, and optimizing model formats before moving the best pieces into the backend.
